If you have solar panels or a home battery, you rarely know how much you use
yourself, how much goes to the grid, and when the battery is working. This guide
gets the three flows into Home Assistant and uses them for a simple automation
that shifts consumption to hours with surplus.

You get an Energy dashboard with production, grid and battery, a solar forecast,
and an automation for one load that may switch on and off without you. You need
counters or an integration from your inverter, and Energy must already work with
the grid; see [Energy Dashboard](/en/home-assistant/energy-dashboard/) and, if
you read live from the meter, [your meter via the HAN port](/en/home-assistant/elmaaler-han-port/).

## Choose how the data gets in

Home Assistant's [solar panels page](https://www.home-assistant.io/docs/energy/solar-panels/)
names two main routes to production data: CT clamps, which measure current in a
wire, and inverter APIs that an integration can read. Shelly EM is the
off-the-shelf option the page recommends, and ESPHome can be used for a DIY
build. The battery page similarly names a vendor integration (for example Tesla
Powerwall) or CT clamps.

| Source | Suits | You maintain |
|---|---|---|
| Integration for your inverter or battery | The manufacturer has an integration | The integration's status and login |
| Shelly EM or another CT meter | The inverter has no usable integration | The meter, its placement and firmware |
| ESPHome with a CT sensor | You want to build it yourself | Configuration and calibration |

<Aside type="caution" title="CT clamps need an open cabinet">
Home Assistant writes that fitting CT clamps requires opening the electrical
cabinet and that a qualified installer should do it. In some places the rules
require a licensed electrician. Use an integration if you can, and have an
electrician fit the clamps.
</Aside>

## Step by step

<Steps>
1. **Find the sensors**

   Use **Settings → Tools → States** to find the sensors from your integration.
   You need energy (kWh) that rises continuously for each of these: grid
   consumption, grid export, solar production, energy into the battery and
   energy out of the battery. See the
   [Energy overview](https://www.home-assistant.io/docs/energy/) for the
   requirements on units and power sensors.

2. **Add the grid first**

   Under **Settings → Dashboards → Energy** choose **Add grid connection** and
   select the sensors for consumption and, if you have it, export. See
   [Energy Dashboard](/en/home-assistant/energy-dashboard/).

3. **Add solar panels**

   Select the inverter's cumulative production. Do not use grid export as
   production; own consumption would be missing.

4. **Add the battery**

   Select the sensors for energy in and energy out. A percentage (state of
   charge) is useful for operation but does not replace the two energy sensors.
   Check sign and direction; some inverters report discharge as negative power.

5. **Turn on the solar forecast**

   Add the [Forecast.Solar](https://www.home-assistant.io/integrations/forecast_solar/)
   integration under **Settings → Devices & services**. You enter the tilt (0 is
   flat, 90 is upright), the azimuth (0 is north, 180 is south) and the total
   peak power in Wp. Then go to Energy, the Solar panels section, turn on the
   forecast and select Forecast.Solar.

6. **Create a surplus sensor**

   Create a Threshold helper under **Settings → Devices & services → Helpers →
   Create helper → Threshold**. Choose a sensor that shows the power you send to
   the grid (positive when exporting), and set an upper limit, for example
   1500 W, and a hysteresis, for example 200 W. With only an upper limit the
   sensor turns on when the value exceeds the limit plus hysteresis and turns off
   when it falls below the limit minus hysteresis. See the
   [Threshold integration](https://www.home-assistant.io/integrations/threshold/).
   We call the helper `binary_sensor.solcelle_overskud` here.

7. **Create the automation**

   Create an empty automation, open the three-dot menu and choose **Edit in
   YAML**. Paste the example below and replace the entity IDs.
</Steps>

### Automation: run a load on surplus

The example uses a state trigger with `for:`, so a short passing cloud does not
switch the load on and off all the time. Home Assistant states that the timer
resets when it restarts or automations reload. Choose a load that tolerates
being switched off, for example a hot water tank with its own thermostat.

```yaml title="Automation: Load follows solar surplus"
alias: "Load follows solar surplus"
description: "Switches a load on at steady surplus and off again"
triggers:
  - trigger: state
    entity_id: binary_sensor.solcelle_overskud
    to: "on"
    for: "00:05:00"
    id: surplus_on

  - trigger: state
    entity_id: binary_sensor.solcelle_overskud
    to: "off"
    for: "00:05:00"
    id: surplus_off

  - trigger: state
    entity_id: binary_sensor.solcelle_overskud
    to: "unavailable"
    for: "00:10:00"
    id: sensor_lost

conditions: []

actions:
  - choose:
      - conditions:
          - condition: trigger
            id: surplus_on
        sequence:
          - action: switch.turn_on
            target:
              entity_id: switch.varmtvandsbeholder

      - conditions:
          - condition: trigger
            id:
              - surplus_off
              - sensor_lost
        sequence:
          - action: switch.turn_off
            target:
              entity_id: switch.varmtvandsbeholder

mode: restart
```

If you switch it off by hand, the automation does not switch it on again until
the sensor goes `on` anew. To switch on only when the battery is reasonably full,
add a condition to the first branch. The official
[numeric_state condition](https://www.home-assistant.io/conditions/numeric_state/)
fails if the sensor is `unavailable` or `unknown`:

```yaml
          - condition: numeric_state
            entity_id: sensor.batteri_ladetilstand
            above: 80
```

To shift use by price instead, see the
[electricity price integration](/en/home-assistant/elpris-integration/) and
[EV preheating](/en/home-assistant/elbil-opvarmning/). For an overview of the
ways to measure, see [energy management](/en/produkter/energistyring/).

## Test it

1. In Energy the grid, solar panels and battery should show numbers after the
   next statistics period. Compare today's production with the inverter's own
   display; large deviations point to the wrong sensor or unit.
2. On a sunny midday, watch the surplus sensor under **Settings → Tools →
   States**. Switch on a known load, for example a kettle; the sensor should
   change when export drops.
3. Open the automation's trace under **Activity** and check that it ran the
   right branch; see [Activity and Traces](/en/home-assistant/aktivitet-og-spor/).
   **Run actions** does not supply a trigger ID, so test with a real change.
4. Check that the load actually switched on and off, not only that the
   dashboard changed.
5. Compare tomorrow's forecast with actual production for a few days.
   Forecast.Solar itself says the forecast is an estimate.

## When it does not work

| Symptom | Possible cause | Next step |
|---|---|---|
| The sensor cannot be chosen in Energy | Wrong unit, device class or state class | See [Energy Dashboard](/en/home-assistant/energy-dashboard/) |
| Production and grid are counted twice | The same energy exists as both total and sub-total | Remove one |
| The battery shows negative values | Discharge is reported with a sign | Use separate energy sensors for in and out |
| The forecast is empty | The integration is not selected in Energy | Turn on the forecast under Solar panels |
| The load switches on and off constantly | The limit is too close to typical export | Increase the hysteresis or `for:` |
| The load stays on after a restart | The `for:` timer resets at restart | Add a start trigger if you want one |

## Undo

Disable the automation and switch the load on or off by hand. Delete the
Threshold helper under **Helpers**, and remove solar panels or battery under
**Settings → Dashboards → Energy**. History in Home Assistant is kept.
