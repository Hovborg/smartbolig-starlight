The electricity price changes through the day, and many appliances do not care
when they run as long as they are done by a certain time. Here you let Home
Assistant find the cheapest **continuous** window before your deadline and start
the appliance then. You stay in control: one switch plans, and if you turn it
off, nothing happens.

The guide uses Home Assistant's own
[Nord Pool integration](https://www.home-assistant.io/integrations/nordpool/).
How to install a price integration with Danish tariffs is covered in
[Electricity price integration](/en/home-assistant/elpris-integration/) and is
not repeated here. Other appliances that can follow the price are covered in
[EV pre-heating](/en/home-assistant/elbil-opvarmning/) and
[Washing machine notification](/en/home-assistant/vaskemaskine-notification/).
For measuring consumption, see [Energy management](/en/produkter/energistyring/).

## What you get

- A switch you turn on when the appliance is loaded and ready.
- An automation that calculates the cheapest start from the prices and your deadline.
- A message with the start time and the price difference.
- The option to cancel or start manually at any time.

## What you need

- The Nord Pool integration set up with your price area.
- An appliance you can switch on and off from Home Assistant, for example through
  a smart plug.
- A figure for the appliance's consumption per run if you want to see a saving.

<Aside type="caution" title="Not every appliance can be started by power">
A plug that cuts and restores power only starts appliances that begin by
themselves when power returns. Many dishwashers and washing machines need a
press on start; check the manual for your model. A water heater or a heat pump
often has a setting or an integration instead. The plug must be rated for the
appliance's power, so compare the markings on both. Never touch the fixed
installation to get control; that is work for an authorised installer.
</Aside>

## How the plan works

| Situation | Result |
|---|---|
| You turn planning on | The automation fetches today's and tomorrow's prices |
| The prices cover a window before the deadline | The cheapest continuous window is chosen |
| Starting now is cheapest | The appliance starts in about a minute |
| Tomorrow's prices are not ready | You get a message and the plan is dropped |
| You turn the switch off before the start | The appliance is not started |

The price unit does not matter for the comparison itself. According to the
documentation the action returns the price per MWh, and the message below
divides by 1000 to show the price per kWh.

## 1. Create the helpers

<Steps>
1. Go to **Settings → Devices & services → Helpers**.
2. Create a **Toggle** named `Opvask – kør billigt` with the entity ID
   `input_boolean.billig_opvask`.
3. Create a **Date and/or time** helper with time only, named
   `Opvask – færdig inden`, with the ID `input_datetime.billig_opvask_frist`.
   Set 07:00, for example.
4. Create a **Date and/or time** helper with both date and time, named
   `Opvask – planlagt start`, with the ID `input_datetime.billig_opvask_start`.
</Steps>

Without a fixed initial value, the helpers normally restore their last value
after a restart. This is described for both
[input_datetime](https://www.home-assistant.io/integrations/input_datetime/) and
[input_boolean](https://www.home-assistant.io/integrations/input_boolean/).

## 2. Find your config entry ID

The action needs to know which Nord Pool setup to use. Open Developer tools,
choose the actions tab, find `nordpool.get_prices_for_date`, and switch to YAML
view. The documentation describes reading the ID there. Copy it into
`config_entry` below.

## 3. Create the planner

Create an empty automation, choose **Edit in YAML**, and paste the example.
Change `DK1` to the area code your integration uses, insert your ID, and enter
your own consumption per run.

```yaml title="Automation: Plan the cheapest start"
alias: "Dishwasher: plan the cheapest start"
description: "Finds the cheapest continuous window before the deadline"
triggers:
  - trigger: state
    entity_id: input_boolean.billig_opvask
    to: "on"

actions:
  - variables:
      omraade: "DK1"
      varighed_minutter: 180
      forbrug_kwh: 1.0   # REPLACE with your own measured consumption per run

  - action: nordpool.get_prices_for_date
    data:
      config_entry: "YOUR_CONFIG_ENTRY_ID"
      date: "{{ now().date() }}"
      areas: "{{ omraade }}"
    response_variable: priser_i_dag

  - action: nordpool.get_prices_for_date
    data:
      config_entry: "YOUR_CONFIG_ENTRY_ID"
      date: "{{ now().date() + timedelta(days=1) }}"
      areas: "{{ omraade }}"
    response_variable: priser_i_morgen

  - variables:
      plan: |-
        {%- set slots = (priser_i_dag[omraade] | default([])) + (priser_i_morgen[omraade] | default([])) %}
        {%- set dur = varighed_minutter * 60 %}
        {%- set t_now = as_timestamp(now()) + 60 %}
        {%- set frist = today_at(states('input_datetime.billig_opvask_frist')) %}
        {%- set frist_ts = as_timestamp(frist if frist > now() else frist + timedelta(days=1)) %}
        {%- macro snit(start) -%}
          {%- set m = namespace(sum=0, daekket=0) -%}
          {%- for p in slots -%}
            {%- set fra = [as_timestamp(p.start), start] | max -%}
            {%- set til = [as_timestamp(p.end), start + dur] | min -%}
            {%- if til > fra -%}
              {%- set m.sum = m.sum + p.price * (til - fra) -%}
              {%- set m.daekket = m.daekket + (til - fra) -%}
            {%- endif -%}
          {%- endfor -%}
          {{ (m.sum / m.daekket) if m.daekket >= dur - 1 else 'x' }}
        {%- endmacro %}
        {%- set nu_pris = snit(t_now) | trim %}
        {%- set ns = namespace(start=none, bedst=none) %}
        {%- if nu_pris != 'x' and t_now + dur <= frist_ts %}
          {%- set ns.start = t_now %}
          {%- set ns.bedst = nu_pris | float %}
        {%- endif %}
        {%- for p in slots %}
          {%- set s = as_timestamp(p.start) %}
          {%- if s > t_now and s + dur <= frist_ts %}
            {%- set v = snit(s) | trim %}
            {%- if v != 'x' and (ns.bedst is none or v | float < ns.bedst) %}
              {%- set ns.start = s %}
              {%- set ns.bedst = v | float %}
            {%- endif %}
          {%- endif %}
        {%- endfor %}
        {{- {'start': ns.start, 'bedst': ns.bedst, 'nu': (nu_pris | float) if nu_pris != 'x' else none} }}

  - choose:
      - conditions:
          - condition: template
            value_template: "{{ plan.start is none }}"
        sequence:
          - action: persistent_notification.create
            data:
              notification_id: billig_opvask
              title: "Dishwasher: no plan"
              message: >-
                There were not enough prices for a continuous window before the
                deadline. Tomorrow's prices may not be published yet, or the
                run is too long for the window.
          - action: input_boolean.turn_off
            target:
              entity_id: input_boolean.billig_opvask
    default:
      - action: input_datetime.set_datetime
        target:
          entity_id: input_datetime.billig_opvask_start
        data:
          timestamp: "{{ plan.start }}"
      - action: persistent_notification.create
        data:
          notification_id: billig_opvask
          title: "Dishwasher: planned"
          message: >-
            Start {{ plan.start | timestamp_custom('%d.%m. at %H:%M') }}.
            Average price in the window: {{ (plan.bedst / 1000) | round(2) }}
            per kWh
            {% if plan.nu is not none %}versus {{ (plan.nu / 1000) | round(2) }}
            per kWh if started now. Difference for a run of {{ forbrug_kwh }} kWh:
            {{ ((plan.nu - plan.bedst) / 1000 * forbrug_kwh) | round(2) }}{% endif %}.

mode: single
```

The template compares windows using the timestamps the action returns, and
weights each price by how long it applies. It therefore works with both hourly
and 15-minute prices; the Nord Pool documentation describes the market moving
to 15-minute resolution. According to the integration's source code the action
returns an empty list for a day without prices, so in that case the template
reports no plan instead of failing.

## 4. Create the starter

```yaml title="Automation: Start at the planned time"
alias: "Dishwasher: start at the planned time"
description: "Starts the appliance if the plan is still switched on"
triggers:
  - trigger: time
    at: input_datetime.billig_opvask_start

conditions:
  - condition: state
    entity_id: input_boolean.billig_opvask
    state: "on"

actions:
  - action: switch.turn_on
    target:
      entity_id: switch.opvasker_stikkontakt
  - action: input_boolean.turn_off
    target:
      entity_id: input_boolean.billig_opvask

mode: single
```

According to the documentation for
[time triggers](https://www.home-assistant.io/triggers/time/), a trigger using a
helper with both date and time fires once at that moment. The starter is
separate from the planner, so the plan survives a Home Assistant restart. If the
appliance runs until it finishes by itself, you need nothing more. If a heat
source must be switched off again, you can add `delay` and `switch.turn_off`;
the [delay documentation](https://www.home-assistant.io/building-blocks/delay/)
says that a waiting automation is stopped by a restart and does not resume.

## Test it

1. Prepare the appliance with the power cut, and set the deadline to a time in
   the future.
2. Turn `Opvask – kør billigt` on.
3. Check the notifications for a plan with a start time and price.
4. See that `Opvask – planlagt start` has the same time.
5. Turn the switch off and on again, and see that the start time is recalculated.
6. Turn the switch off before the start time, and check that nothing starts.
7. Let a plan run, and check that the plug switches on at the time.

Use [Activity and Traces](/en/home-assistant/aktivitet-og-spor/) to see what the
automations did and why.

## See whether it saves anything

The message shows the difference per kWh and for the consumption value you
entered yourself. It is the spot price that is compared. If your grid company
has time-dependent grid tariffs, they are not included, and your real
difference may be different;
[Electricity price integration](/en/home-assistant/elpris-integration/) describes
an integration that includes tariffs and taxes. Measure consumption with an
energy meter, and keep your own figures over a few weeks before concluding
anything.

## Troubleshooting

| Symptom | Possible cause | What to do |
|---|---|---|
| No plan, message about missing prices | Tomorrow's prices have not been fetched yet | Turn the switch on again later |
| Error in the action | Wrong config entry ID or area code | Fetch the ID again in Developer tools |
| Nothing starts | The switch was turned off, or Home Assistant was down at the start time | Turn it off and start the appliance manually |
| Power is on but the appliance does not run | The model needs a press on start | Use the appliance's own integration or another start signal |
| The start time is late | The deadline is set late | Move the deadline |

## How to undo it

Turn the switch off, and the plan stops. Delete the two automations and the
three helpers if you want to remove everything. The plug and the appliance are
unchanged and work as before.

The YAML examples are checked for syntax, and the template logic was tried with
made-up price data outside Home Assistant. Try them on your own system using the
steps above before you let them control anything day to day.
