When you go away, you do not want to think about heating, lamps and alerts one
by one. Here you gather them behind one switch, `input_boolean.ferietilstand`.
Turn it on, and the heating is lowered, the lights simulate that someone is
home, and the alerts become sharper. Turn it off, and everything is put back,
whether you do it yourself or Home Assistant sees you arrive.

The guide is built from helpers, a schedule and five automations. If
automations are new to you, begin with
[your first automation](/en/home-assistant/foerste-automation/). If the message
should reach several phones, see
[Send one message to several phones](/en/home-assistant/mobilnotifikationer/).

<Aside type="caution" title="Not a replacement for your alarms">
Let your smoke alarms and water alarms work on their own. Home Assistant gives
an extra message while you are away, but a message needs internet and a phone
that receives it. Choose a vacation temperature that keeps the home safe from
frost; never turn the heating off completely, and check your heating system's
manual for a lower limit.
</Aside>

## What you get

- The heating goes to a vacation temperature and back to normal when the mode is turned off.
- Lights that switch on and off with some random offset inside a time window.
- A message when a door opens while vacation mode is on.
- A stronger alert for water leaks and smoke while you are away.
- Automatic end of the mode when a person gets home.

## What you need

- At least one thermostat as a `climate` entity, for example `climate.stue`.
- One or more lamps Home Assistant can switch on and off.
- A door sensor, a water leak sensor and a smoke alarm Home Assistant can read.
- The phone app, so you can receive messages.
- A `person` entity for each resident.

Binary sensors use the states `on` and `off`. For doors, `on` means open; for
moisture, `on` means wet; and for smoke, `on` means smoke detected. This is
described in the documentation for
[binary sensors](https://www.home-assistant.io/integrations/binary_sensor/).

## How vacation mode behaves

| Situation | Result |
|---|---|
| Vacation mode is turned on | Heating is set to the vacation temperature |
| The lighting schedule starts | One lamp switches on after a random delay |
| The lighting schedule ends | The lamps switch off after a random delay |
| A door opens during vacation | You get a message |
| Water leak or smoke | You get a message; a strong one during vacation |
| A person gets home | Vacation mode is turned off |
| Vacation mode is turned off | Heating is restored; lamps switch off if the schedule has ended |

## 1. Create the helpers

<Steps>
1. Go to **Settings → Devices & services → Helpers**.
2. Create a **Toggle** named `Ferietilstand` with the ID
   `input_boolean.ferietilstand`.
3. Create two **Number** helpers: `Feriestemperatur`
   (`input_number.ferie_temp_ferie`) and `Normal temperatur`
   (`input_number.ferie_temp_normal`). Set your own limits, step and values.
4. Create a **Schedule** named `Ferielys` (`schedule.ferielys`). Draw the time
   windows when lights should be on, for example the evening every day.
</Steps>

A schedule is `on` inside its time windows and `off` outside them. It can be
used as a trigger and a condition, and its `next_event` attribute shows the next
change. See the
[Schedule documentation](https://www.home-assistant.io/integrations/schedule/).
A number helper normally restores its last value after a restart if you have
not set an initial value in YAML; see
[Input number](https://www.home-assistant.io/integrations/input_number/).

## 2. Heating: on and off

The action `climate.set_temperature` sets the target; `hvac_mode` can be left
out so the thermostat keeps its mode. Which features a thermostat has depends on
the model, so try the action on your own thermostat first. See
[climate.set_temperature](https://www.home-assistant.io/actions/climate.set_temperature/).
If your thermostat has a low/high range instead of a single target, the action
uses the fields `target_temp_low` and `target_temp_high`.

Create two automations.

```yaml title="Automation: Vacation on, heating down"
alias: "Vacation: heating down"
description: "Sets the heating to the vacation temperature"
triggers:
  - trigger: state
    entity_id: input_boolean.ferietilstand
    to: "on"

actions:
  - action: climate.set_temperature
    target:
      entity_id: climate.stue
    data:
      temperature: "{{ states('input_number.ferie_temp_ferie') | float }}"

mode: single
```

```yaml title="Automation: Vacation off, everything back"
alias: "Vacation: everything back"
description: "Restores heating and switches off leftover lights when vacation mode ends"
triggers:
  - trigger: state
    entity_id: input_boolean.ferietilstand
    to: "off"

actions:
  - action: climate.set_temperature
    target:
      entity_id: climate.stue
    data:
      temperature: "{{ states('input_number.ferie_temp_normal') | float }}"
  - if:
      - condition: state
        entity_id: schedule.ferielys
        state: "off"
    then:
      - action: light.turn_off
        target:
          entity_id:
            - light.stue
            - light.koekken

mode: single
```

The lamps are only switched off if the schedule is not inside a time window. If
you get home in the middle of the evening, you control the lights yourself. If
the switch is on after a restart but the heating is not set, turn the switch off
and on again. The trigger reacts to the change, not to the state.

## 3. Lights: simulate presence

The automation reacts when the schedule changes, waits a random number of
seconds, and switches on or off. A delay can be a template, and a whole number
means seconds; see [Delay](https://www.home-assistant.io/building-blocks/delay/).

```yaml title="Automation: Vacation lights"
alias: "Vacation: lights as if someone is home"
description: "Switches lamps on and off during the schedule's time windows"
triggers:
  - trigger: state
    entity_id: schedule.ferielys
    to: "on"
    id: lys_til
  - trigger: state
    entity_id: schedule.ferielys
    to: "off"
    id: lys_fra

conditions:
  - condition: state
    entity_id: input_boolean.ferietilstand
    state: "on"

actions:
  - delay: "{{ range(60, 1500) | random }}"
  - choose:
      - conditions:
          - condition: trigger
            id: lys_til
        sequence:
          - action: light.turn_on
            target:
              entity_id: "{{ ['light.stue', 'light.koekken'] | random }}"
      - conditions:
          - condition: trigger
            id: lys_fra
        sequence:
          - action: light.turn_off
            target:
              entity_id:
                - light.stue
                - light.koekken

mode: restart
```

A waiting run is stopped if Home Assistant restarts, and does not resume. If a
restart falls in the middle of an evening, the light may therefore miss turning
on or off that day. Check the lights if you are away for a long time.

## 4. Alerts: door, water leak and smoke

Replace `notify.mobile_app_din_telefon` with your own device. The name of the
triggering entity can be used in the message as `trigger.to_state.name`; see
[templating in automations](https://www.home-assistant.io/docs/automation/templating/).

```yaml title="Automation: Door opened during vacation"
alias: "Vacation: door opened"
description: "Sends a message if a door opens during vacation mode"
triggers:
  - trigger: state
    entity_id: binary_sensor.hoveddoer
    to: "on"

conditions:
  - condition: state
    entity_id: input_boolean.ferietilstand
    state: "on"

actions:
  - action: notify.mobile_app_din_telefon
    data:
      title: "Vacation: door opened"
      message: "{{ trigger.to_state.name }} has been opened."

mode: queued
```

Water leaks and smoke should alert all year round, but during vacation the
alert should ring through. The Companion app documents critical notifications,
and the fields differ between the two platforms. The example shows Android;
switch to the iPhone tab if you use that.

local push is not used, and they do not override Do Not Disturb. On iPhone,

## 5. End automatically when someone gets home

A `person` entity has the state `home`, `not_home` or a zone name. A state
change to `home` can be used as a trigger. After a restart the state may briefly
come from a stationary tracker, so check this; see the
[Person documentation](https://www.home-assistant.io/integrations/person/).

```yaml title="Automation: Turn vacation off on arrival"
alias: "Vacation: someone gets home"
description: "Turns vacation mode off when a person arrives"
triggers:
  - trigger: state
    entity_id:
      - person.anna
      - person.bo
    to: "home"

conditions:
  - condition: state
    entity_id: input_boolean.ferietilstand
    state: "on"

actions:
  - action: input_boolean.turn_off
    target:
      entity_id: input_boolean.ferietilstand

mode: single
```

Do not add a guest, a neighbour or a house sitter as a `person` here, or their
visit will end vacation mode.

## Test it

1. Turn `Ferietilstand` on, and see that the thermostat's target becomes the
   vacation temperature.
2. Add a window to the schedule that starts in a few minutes, and see that a lamp
   switches on after the delay.
3. Open the door sensor, and see that the message arrives.
4. Try water leak and smoke with the device's own test function if it sends a
   change to Home Assistant. Otherwise you can change the entity's state in
   Developer tools. That only changes what Home Assistant believes, not the
   device.
5. Turn the switch off, and see that heating and lights are restored.
6. Turn it on again, and let a person arrive in the home zone.

Use [Activity and Traces](/en/home-assistant/aktivitet-og-spor/) to see which
automations ran.

## Troubleshooting

| Symptom | Possible cause | What to do |
|---|---|---|
| The heating does not change | The thermostat uses other fields | Check the action's fields and try it in Developer tools |
| The lights do not switch on | The schedule is outside a window, or the switch is off | Check `schedule.ferielys` and the switch |
| No message | Wrong notify name | Find your device under the actions in Developer tools |
| Vacation mode ends while you are away | A tracker reports `home` | Check the person's trackers |
| Door alerts arrive all year | The condition is missing | Check that the switch is a condition |

## How to undo it

Turn `Ferietilstand` off. That runs the restore automation and puts heating and
lights back. To remove everything, delete the five automations, the schedule
and the other three helpers. Your thermostats, lamps and sensors are unchanged.

The YAML examples are checked for syntax but have not been tried on a live
system. Try them step by step before you leave.
