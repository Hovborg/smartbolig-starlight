# SmartBolig development

This repository builds smartbolig.net with Astro 7, Starlight 0.41 and a Cloudflare Worker with Static Assets. The separate hub is outside this repository.

- Test the site with `npm run site:test`, news tooling with `npm run ai-news:test`, and content-audit behavior with `python -m unittest discover -s scripts -p "test_*.py"`.
- Before publishing, run `npm run ai-news:validate`, `python scripts/content-audit.py`, `npm audit --audit-level=high`, `npm run build`, `npm run seo:validate`, `npm run worker:build`, and `npx wrangler deploy --dry-run`. Use the locally configured Python executable; Unix CI uses `python3`.
- Include development dependencies in security checks. They execute during local builds and deployment.
- Dependabot opens the dependency pull requests; small npm updates (patch, and minor from version 1) merge on their own after the `deploy` check (`.github/workflows/dependabot-automerge.yml`). Add a new 0.x dependency to `exclude-patterns` in `.github/dependabot.yml`. Read `docs/opdateringer.md` before changing that workflow or `.github/dependabot.yml`. `main` must stay without branch protection: the news workflow pushes to it.
- External news fetches must use `fetchPublicText` from `scripts/lib/ai-news-discovery.mjs`. Preserve official-source validation, per-hop host checks, validated-address pinning, whole-request deadlines and streamed byte ceilings. Use injected transports/DNS in tests; never fetch internal hosts to demonstrate a security issue.
- Windows content checks use native Git for Windows Bash and stdin. Do not introduce WSL dependencies.
- MCP servers are managed by the developer's host configuration. Do not add repository-triggered `npx -y` or mutable `@latest` server installs.
- Keep both locales and shared RSS behavior aligned. Test English-only news edits as well as Danish edits.
- A local build or deployment dry run does not verify production bindings, real AI inference or a GitHub Actions run. Report those boundaries explicitly.
- The daily news is written, fact-checked and published by `.github/workflows/ai-news.yml`; read `docs/nyhedsflow.md` before changing it. The two daily runs each have a stand-in a few hours later; `scripts/ai-news-slot.mjs` keeps a stand-in quiet when the run it stands in for has started. Each story is written and checked on its own in `scripts/lib/news-llm/` (one responsibility per file, shared limits in `limits.mjs`). Never publish copy without a passed fact check, and never loosen the source, duplicate or evidence rules to get more days published.
- Model calls cost money above Cloudflare's free daily allowance. The relay `workers/news-llm/` enforces a daily neuron ceiling and the run has its own ceilings; do not raise them, and do not call the live relay from tests. A live run counts against the day's budget.
- Redesign work in progress is tracked in `docs/redesign/STATUS.md` (done, next step), with choices in `docs/redesign/BESLUTNINGER.md` and items that need the owner in `docs/redesign/TIL-EJEREN.md`. Update them in the same commit as the change.
- Pictures in a guide's text live in `src/assets/guides/` and are written relative to the MDX file; `docs/billeder.md` says how the widths and `sizes` work and what to re-measure after a layout change.
- Product links live in one register, `src/data/products/` (one file per group); guides write `<AffiliateLink product="id" />` and never a shop URL. `docs/indtjening.md` says how to add or fix one; `scripts/site-affiliate-products.test.mjs` fails on unknown or unused products.
- Redirects, `robots.txt`, structured data and social meta are described in `docs/seo.md`; read it before changing `public/_redirects`, `public/robots.txt` or `src/lib/seo/`. `npm run seo:validate` checks the built pages.
- The assistant searches the site's own index (`functions/lib/site-search/`, built by `scripts/site-index.mjs` as the last step of `npm run build`). Read `docs/assistent.md` before changing it. `tokens.js` is shared by the builder and the Worker: a change there changes both. A failed search probe stops the build on purpose; fix the page or the probe, do not remove the check.
- `llms.txt` is written by the build (`scripts/write-llms-txt.mjs`, after `finalize-build.mjs`); there is no `public/llms.txt`. Sections and exclusions are in `scripts/lib/llms-txt.mjs`; see `docs/seo.md`.
- `.github/workflows/monitor.yml` checks the live site three times a day with `scripts/monitor/` and keeps one GitHub issue labelled `monitor` open while a check fails. It needs no secrets and sends no chat question. Read `docs/overvaagning.md` before adding a check or changing the schedule.
- Nothing that sets cookies or sends visitor data to a third party may be loaded from a page's own markup or from `config/head/`: it is fetched by `src/lib/consent/boot.mjs` after a yes. Read `docs/samtykke.md` first, and keep the cookie policy (both languages) in step with the code.
- `SECURITY.md` tells outsiders how to report a problem; keep it true when the protections change.
- Security headers and the Content-Security-Policy live in `public/_headers`; the build adds a stricter policy without `'unsafe-inline'` for scripts (`scripts/lib/csp-inline.mjs`). Read `docs/sikkerhed.md` before adding a host or an inline script.
- Site configuration lives in `config/` (`site.mjs`, `fonts.mjs`, `sidebar/`, `head/`, `components.mjs`). Keep `astro.config.mjs` a thin entry that only wires those modules together; add sidebar entries or head tags in their module, not in the entry.
